# YING OS 功能审查与使用指南

审查日期：2026-10-18。以下区分代码实现、本地验证、线上配置；不把功能对标当作临床可用性评估。

## 课程笔记与聊天整理

日历 →「笔记」→「导入聊天 / 课堂笔记」。可粘贴课堂对话或上传 TXT、Markdown、ChatGPT JSON。没有直接读取其他 ChatGPT 聊天的权限或连接，用户授权不会自动产生这种访问能力。

1. 选择课程，例如 C4D；未分类时规则会尝试识别明确课程名。用完整日期或“第几课 / Session”分开课次；没有明确年份日期时保留日期待确认。
2. 生成知识点、操作步骤、问题、待办四部分；完整输入保存在私有导入批次，每篇笔记保留原文片段。AI 回答与模型整理均标为未核实，不把内容整理当作事实核验。
3. 预览标题、日期、正文与建议日程关联。`[[唯一笔记标题]]` 可跳转，重名时使用 `[[note-UUID]]`；可以查看反向链接。独立笔记可关联多个日程，删除日程不删除笔记。
4. 完全相同来源默认跳过。同课程、标题、日期可能重复时必须选择更新、另存或跳过；未解决的重复不能批量确认。更新检查版本，避免覆盖另一个窗口的修改。
5. 点击一键确认：数据库事务原子提交整批笔记、来源及关联。失败不留下半批笔记；重复确认不重复写入。

规则模式可以使用；AI 模式需要在 **Vercel 服务端**设置 `OPENAI_API_KEY`，可选 `OPENAI_NOTES_MODEL`。界面检查运行环境是否配置，用户主动选择 AI 后才将此次文本和候选日程发送至 OpenAI。当前开发环境无模型密钥，真实模型调用尚未验证。规则不能像模型一样理解任意散乱聊天，建议清晰分课次。

每次最多 4 MB、60,000 字、40 篇提议；笔记索引超过 1,000 条时导入明确停止，避免在不完整索引下误判重复。PDF可在事件看板上传阅读和批注；**PDF 全文提取/OCR 与整本文档自动拆课尚未实现**。

## 删除与恢复

| 内容 | 操作与效果 |
| --- | --- |
| 日程 | 移入回收站、恢复、永久删除；移入时停止相关待发送提醒，恢复产生待批准提醒建议，不擅自恢复批准 |
| 独立笔记 | 回收站、恢复、永久删除；笔记永久删除会清理来源、修订及关联，不删除日程或其他笔记 |
| 看板便签、图片、PDF、链接 | 删除卡片或清空看板；私有附件通过 Storage API 删除，失败保留清理队列可重试；永久操作有确认 |
| 连线与荧光笔 | 连线可删除；橡皮擦按整条笔画擦除，可在当前视图撤销；PDF 每页笔画独立 |
| 准备任务、提醒建议 | 删除并清理相关待处理投递；已进入发送流程时拒绝清理，避免状态不一致 |
| 导入提议和批次 | 可删除；删除笔记导入批次不删除已发布笔记及其原文片段 |
| 来源、笔记原文片段、修订、活动历史 | 在对应详情或“更多与管理 → 数据管理”删除；不改变当前正文；完整清理需同时处理导入批次中的全文 |
| 通知历史 | 删除已结束记录；保留不可读的去重哈希，避免清空日志触发旧通知重发 |
| 简报计划 | 设置中可删除；恢复缺失默认计划时默认关闭，不改变已有时间、静音或频道 |
| 账号 | 数据管理高级区输入明确确认文字后删除本人账号、数据库内容及附件；先验证服务端权限，不可用时不动文件；未执行真实账号删除测试 |

已发送的 Telegram 消息不能由网站删除历史撤回；已交给 Telegram 的在途消息也无法保证取消。删除本地内容不会自动删除第三方 AI 服务端日志。去重哈希随账号级联删除。个人资料不会提交至公共 GitHub。

## 对标与改善优先级

| 对标 | 已实现 | 仍有差距 / 建议 |
| --- | --- | --- |
| Obsidian | 课程和课次独立笔记、内部链接、反向链接、全局搜索、关联图、Markdown ZIP 导出 | 本地 Vault 实时双向同步、插件生态、完整 Markdown 渲染、嵌入块与稳定块引用尚无；先补草稿恢复和更清晰的重名处理 |
| Notion | 四段结构、来源追溯、导入预览、一键事务确认、版本记录、回收站 | 不支持完整富文本块、数据库自定义属性/视图或多人协作；优先补标签管理及批量选择，避免界面过载 |
| Figma | 看板拖动、缩放、长按连线、空白处新建关联便签、图片等比缩放、PDF 翻页、批注和橡皮擦 | 没有全局撤销栈、多人光标、矢量编辑和复杂布局；长按发现性不足，下一步加明显连接柄与键盘替代操作 |

AuDHD 友好设计已采用：日程默认从06:00显示、紧凑日程与按需详情、输入区收起、清晰确认状态、显示保存结果、重要操作可恢复、管理项放入次级导航。仍需真实用户与辅助技术测试，不宣称符合临床或全面 WCAG 标准。

建议顺序：P0 草稿自动恢复和离线失败保护；P1 连接柄、键盘焦点/快捷键说明、批量选择与筛选；P2 大规模图谱布局、标签合并、PDF文本提取。不要同时增加大量默认面板和通知。

## 验证与部署边界

- 单元测试覆盖拆课、原文、重复、关联候选、模型结构验证、认证与删除权限失败保护。
- 临时 PostgreSQL 实测迁移重复执行、RLS、导入事务、重复确认、关联、回收站、附件清理队列、通知去重；不使用真实日程作测试数据。
- Chromium 使用隔离模拟 Supabase 测试看板、搜索及笔记操作；不等同于真实生产账号的端到端验证。
- Google Calendar 目前仅 ICS 导入；OAuth 自动同步未实现。Obsidian 当前是导出兼容，不是实时连接。
- 本次未改 Telegram 凭据、Cron 或静音，也未发送额外测试消息。
